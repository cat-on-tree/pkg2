更新日期：2026-07-02

## 0. 技术路线总览

本研究的核心目标是：

从 PKG 2.0 中构建领域化异构时序知识载体图，将论文、专利、临床试验、项目等对象视为 **knowledge carriers**，而不是知识本身；进一步从 carriers 中抽取真正被传播、积累和转化的知识对象，即 **Knowledge Units**；随后构建 Knowledge State 与 Knowledge Field，最终用于知识转化预测与可解释动态建模。

整体技术路线分为 7 个模块：

```text
1. PKG 2.0 数据预处理
2. Knowledge Carrier Graph 构建
3. Knowledge Unit 定义与抽取
4. Knowledge State 构造
5. Knowledge Field 动态建模
6. 预测任务与模型训练
7. 解释性分析与案例验证
```

# 1. 数据层：PKG 2.0 数据预处理

## 1.1 目标

从 PKG 2.0 中提取论文、专利、临床试验、实体、项目、作者、机构、期刊等多源信息，构建后续模型所需的领域化异构时序图。

## 1.2 输入数据

PKG 2.0 中的核心数据包括：

| 数据类型 | 示例字段 | 作用 |
| --- | --- | --- |
| PubMed papers | PMID, title, abstract, year, journal | 基础研究载体 |
| Patents | patent ID, title, abstract, assignee, year | 技术 / 商业化载体 |
| Clinical trials | NCT ID, title, condition, intervention, phase, start year | 临床转化载体 |

| Citation links | paper-paper, patent-paper | 知识扩散路径 |
| Project links | NIH project-paper, project-patent, project-trial | funding / source term |
| Author / institution | author ID, affiliation, institution | 信誉、扩散网络 |
| Journal metrics | SJR, h-index, impact indicator | reliability / impact proxy |

# 2. 图结构层：Knowledge Carrier Graph 构建

## 2.1 核心思想

传统方法通常把：

```text
Paper
Patent
ClinicalTrial
```

直接视为 knowledge nodes。

本研究的关键区别是：

```text
Paper / Patent / ClinicalTrial / Project = Knowledge Carriers
```

也就是说，论文、专利、临床试验、项目只是知识的承载容器，而不是知识本身。

## 2.2 Carrier Graph 定义

定义：

```text
G_C = (V_C, E_C, T)
```

其中：

```text
V_C = V_Paper
    ∪ V_Patent
    ∪ V_Trial
    ∪ V_Project
    ∪ V_Author
    ∪ V_Institution
    ∪ V_Journal
    ∪ V_BioEntity
```

边类型包括：

| 边类型 | 含义 |
| --- | --- |
| paper cites paper | 学术扩散 |
| patent cites paper | 科学到技术转移 |
| paper linked to trial | 基础到临床转化 |
| trial linked to patent | 临床到商业化 |
| paper funded by project | 外部输入 |
| patent linked to project | 技术开发资金或项目支撑 |
| trial linked to project | 临床研究资金或项目支撑 |
| author writes paper | 人员传播路径 |
| institution hosts trial / paper | 组织传播路径 |
| document mentions entity | carrier 到 Knowledge Unit 的映射基础 |

## 2.3 Carrier Graph 的作用

Carrier Graph 不直接表示知识，而是定义知识可以传播和被观测的空间：

```text
Carrier Graph = Discrete Knowledge Space
```

也可以理解为：

```text
G_C = Graph Mesh
```

在理论框架中，Graph 是离散空间，Carrier Graph 是 Knowledge Field 所在的 mesh。

# 4. 知识对象层：Knowledge Unit 定义与抽取

## 4.1 目标

从 paper、patent、trial 等 carriers 中抽取真正被传播和转化的对象：

```text
Knowledge Unit z
```

而不是把文档本身当作知识。

## 4.2 当前工程选择

当前工程版本采用：

```text
Knowledge Unit = typed BioEntity pair
```

即：

```text
z = (entity_i, entity_j, pair_type)
```

原因：

```text
1. 比单个 entity 更像知识单元；
2. 不需要复杂 NLP relation extraction；
3. 可以直接复用当前 carrier-BioEntity mention graph；
4. 能自然连接 paper / patent / trial evidence；
5. 适合后续构建 yearly temporal panel；
6. 可作为 relation-level KU 的前置版本。
```

## 4.3 当前主版 pair types

当前主版 demo 数据集采用 translational / mechanistic pair types：

```text
chemical-disease
gene-disease
chemical-gene
```

当前不把 `disease-disease` 放入主版。

理由：

```text
disease-disease 共现混合了多种语义关系，包括：
1. comorbidity
2. complication
3. risk factor
4. subtype hierarchy
5. near-synonymy
6. background co-mention
```

例如：

```text
diabetes - type 2 diabetes
type 1 diabetes - type 2 diabetes
diabetes - obesity
diabetes - hypertension
```

这些 pair 有些有医学意义，但不适合直接与 `chemical-disease`、`gene-disease`、`chemical-gene` 混在主版 translational KU layer 中。

因此当前策略是：

```text
main translational KU layer:
  chemical-disease
  gene-disease
  chemical-gene

future exploratory disease layer:
  disease-disease
```

`disease-disease` 后续可以单独构建为：

```text
disease-disease exploratory comorbidity / disease context layer
```

并需要额外过滤：

```text
ontology hierarchy
synonym / near-synonym
generic disease hubs
comorbidity relation annotation
```

## 4.4 canonicalization 策略

当前已修复 pair canonicalization：

```text
1. 不同类型 pair 按 pair_types 指定方向归一；
2. 同类型 pair 按稳定 entity key 排序；
3. reversed pair duplicate 被消除；
4. KU id 在 canonicalized pair 上生成。
```

sanity check 结果：

```text
Duplicate unordered pairs: 0
```

说明 canonicalization 已通过验证。

# 5. Carrier-to-Knowledge Unit Mapping

## 5.1 核心映射

一个 knowledge unit 可以被多个 carrier 承载：

```text
z -> Paper_1, Paper_2, Trial_1, Patent_1
```

例如：

```text
(metformin, type 2 diabetes)
  -> Paper_A
  -> Paper_B
  -> ClinicalTrial_C
  -> Patent_D
```

这一步相当于从 Carrier Graph 投影出 Knowledge Unit 层：

```text
G_C -> Z + M_{c,z}
```

其中：

```text
M_{c,z} = 1, if carrier c mentions/supports z
M_{c,z} = 0, otherwise
```


# 8. Knowledge State 构造

## 8.1 目标

为每个 knowledge unit 构造状态向量：

```text
K_z(t)
```

它不是普通静态 embedding：

```text
h_z
```

而是具有解释性维度的状态向量。

## 8.2 Knowledge State 定义

建议定义：

```text
K_z(t) = [
  E_z(t),
  N_z(t),
  M_z(t),
  T_z(t),
  R_z(t),
  C_z(t)
]
```

其中：

| 维度 | 含义 |
| --- | --- |
| E_z(t) | Evidence，证据强度 |
| N_z(t) | Novelty，创新性 |
| M_z(t) | Maturity，成熟度 |
| T_z(t) | Translation，临床转化程度 |
| R_z(t) | Reliability，可靠性 |
| C_z(t) | Commercialization，商业化程度 |

## 8.3 当前下一步：rule-based proxy state

## 8.4 第一版 proxy feature 建议

### Evidence proxy

```text
evidence_score =
log1p(paper_count)
+ 0.5 * log1p(total_pair_weight)
```

### Novelty proxy

高 novelty 倾向于：

```text
first_paper_year 较晚
carrier_count 不极高
entity hub degree 不极高
pair specificity 较高
```

### Maturity proxy

高 maturity 倾向于：

```text
first_paper_year 很早
paper_count 高
carrier_count 高
长期持续出现
```

### Translation proxy

```text
translation_score =
I(patent_count > 0)
+ I(trial_count > 0)
+ log1p(patent_count)
+ log1p(trial_count)
```

trial year patch 后，当前可以使用：

```text
first_trial_year
paper_to_trial_lag
trial_count_year
trial_count_cum
first_translation_year
```

### Commercialization proxy

```text
commercialization_score =
I(patent_count > 0)
+ log1p(patent_count)
```

### Discovery score

raw carrier_count top list 会被成熟常识知识主导，例如：

```text
glucose - insulin
insulin - diabetes
glucose - diabetes
```

这些适合作为 sanity check，但不是 discovery output。

后续 discovery ranking 应使用：

```text
discovery_score =
translation_potential_proxy
+ recentness
+ specificity
- maturity_penalty
- hub_penalty
```

目标是突出：

```text
1. 非极端高频 hub pair；
2. 有近期增长的 KU；
3. 有 patent/trial 转化迹象的 KU；
4. paper-only 但具备未来转化潜力的 KU；
5. 更 specific 的 chemical-disease / gene-disease / chemical-gene pair。
```

# 9. Knowledge Field 动态建模

## 9.1 核心思想

所有 knowledge units 的 knowledge states 构成 knowledge field：

```text
K(t) = {K_z(t)}_{z ∈ Z}
```

也就是：

```text
K(t) ∈ R^{|Z| × d}
```

其中：

```text
|Z| = knowledge unit 数量
d = state dimension
```

## 9.2 基础动力学方程

核心模型可写为：

```text
dK(t)/dt = -D L_t K(t) + R_θ(K(t), X(t)) + S_θ(t)
```

其中：

| 项 | 含义 |
| --- | --- |
| K(t) | knowledge field |
| L_t | time-dependent graph Laplacian |
| D | diffusion coefficient |
| -D L_t K(t) | knowledge diffusion |
| R_θ | reaction term，知识增长、衰减、竞争、融合 |
| S_θ(t) | source term，funding、重大项目、政策等外部输入 |

## 9.3 异构边类型扩散

由于 PKG 2.0 是异构图，不同边类型扩散机制不同。

因此定义：

```text
dK/dt = Σ_{r ∈ R} D_r L_r K + R_θ(K, X) + S_θ
```

其中 `r` 是边类型。

| 边类型 r | 含义 |
| --- | --- |
| citation | 学术传播 |
| co-entity | 概念共现 |
| paper-trial | 临床转化 |
| paper-patent | 技术转移 |
| funding | 外部注入 |
| author / institution | 社群传播 |

每种边有自己的 diffusion coefficient：

```text
D_r
```

这样模型可以学习：

```text
citation diffusion 是否主要影响 evidence
patent diffusion 是否主要影响 commercialization
trial diffusion 是否主要影响 translation
funding source 是否促进 novelty 或 maturity
```

## 9.4 Reaction Term

```text
R_θ(K(t), X(t))
```

表示知识自身的非线性变化。

包括：

| 过程 | 示例 |
| --- | --- |
| Growth | citation 增加、重复验证 |
| Decay | 热度下降、临床失败 |
| Competition | 多个 drug target 竞争 |
| Fusion | 两个机制合并为新机制 |
| Saturation | mature knowledge 增长变慢 |
| Translation jump | 进入 trial 后 translation 突增 |

## 9.5 Source Term

```text
S_θ(t)
```

表示外部输入，例如：

```text
NIH funding
大型计划
产业投资
public health emergency
政策推动
breakthrough technology
```

在 PKG 2.0 中最直接的是 NIH project：

```text
S_z(t) = g(funding_amount, project_count, project_duration)
```

# 10. 模型实现层：KFRD-Net / PKF-Net

## 10.1 模型命名

候选名称：

```text
Knowledge Field Reaction-Diffusion Network, KFRD-Net
```

或：

```text
Physics-informed Knowledge Field Network, PKF-Net
```

## 10.2 模型输入

对于每个时间点 `t`：

```text
G_t
X_t
K_t
S_t
Y_t
```

其中：

| 输入 | 含义 |
| --- | --- |
| G_t | 动态图结构 |
| X_t | carrier / knowledge unit 特征 |
| K_t | 当前 knowledge state |
| S_t | funding / source 特征 |
| Y_t | 未来转化标签 |

## 10.3 离散时间更新

```text
K(t + Δt)
= K(t) + Δt [
    Σ_r D_r L_r(t)K(t)
    + R_θ(K(t), X(t))
    + S_θ(t)
  ]
```

也可写为：

```text
K_hat_{t+1}
= K_t + Diffusion_t + Reaction_t + Source_t
```

## 10.4 模型模块

### Module 1：State Encoder

```text
K_t = Encoder(X_t)
```

将原始统计特征转为状态向量。

### Module 2：Diffusion Layer

```text
Diff_t = Σ_r D_r L_r K_t
```

学习不同边类型的扩散系数。

### Module 3：Reaction Network

```text
React_t = MLP_θ([K_t, X_t, ΔX_t])
```

学习知识增长、衰减和跃迁。

### Module 4：Source Network

```text
Source_t = MLP_φ(Funding_t)
```

建模 NIH funding / project 输入。

### Module 5：Prediction Head

输出未来事件概率：

```text
ŷ_{z,t+τ} = Head(K_z(t+τ))
```

例如：

```text
future clinical trial
future patent
future citation growth
future phase advancement
```

# 13. 损失函数设计

总损失可写为：

```text
L = L_pred
  + λ1 L_state
  + λ2 L_smooth
  + λ3 L_physics
  + λ4 L_interpret
```

## 13.1 预测损失

二分类：

```text
L_pred = BCE(y, ŷ)
```

多分类：

```text
L_pred = CE(y, ŷ)
```

时间预测：

```text
L_time = MSE(τ, τ_hat)
```

## 13.2 状态监督损失

如果有 proxy state：

```text
L_state = ||K_z(t) - K_z^proxy(t)||^2
```

## 13.3 平滑性约束

知识状态不应无因剧烈跳变：

```text
L_smooth = Σ_t ||K(t+1) - K(t)||^2
```

但 trial / patent 事件允许 jump，可以使用 event-aware smoothness。

## 13.4 Physics residual loss

如果使用连续形式：

```text
dK/dt + D L K - R_θ - S_θ = 0
```

对应 residual：

```text
L_physics =
|| (K(t+1) - K(t))/Δt + D L K - R_θ - S_θ ||^2
```
