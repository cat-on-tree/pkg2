## 0. 技术路线总览

本研究的核心目标是：

从 PKG 2.0 中构建领域化异构时序知识载体图，将论文、专利、临床试验、项目等对象视为 **knowledge carriers**，而不是知识本身；进一步从 carriers 中抽取 Knowledge Units，并在长时间窗口上建模 Knowledge Units 的时序演化、转化热度和扩散过程。

整体理论主线是：

```text
Carrier Graph
  -> Knowledge Unit Layer
  -> KU Temporal Modeling Dataset
  -> Long-window KU Temporal Prediction Dataset
  -> Temporal Baselines and Ablations
  -> Knowledge Field Reaction-Diffusion-Source Model
  -> Interpretable Knowledge Flow Analysis
```

# 2. Stage 01：Knowledge Carrier Graph Construction

## 2.1 核心思想

传统方法通常把：

```text
Paper
Patent
ClinicalTrial
```

直接视为 knowledge nodes。

本研究的关键区别是：

```text
Paper / Patent / ClinicalTrial / Project = Knowledge Carriers
```

也就是说，论文、专利、临床试验、项目只是知识的承载容器，而不是知识本身。

## 2.2 Carrier Graph 定义

定义：

```text
G_C = (V_C, E_C, T)
```

其中当前实现的核心节点类型包括：

```text
V_C = V_Paper
    ∪ V_Patent
    ∪ V_Trial
    ∪ V_Project
    ∪ V_BioEntity
```

当前实现的核心边类型：

| 边类型 | 含义 |
| --- | --- |
| patent linked to paper | 科学到技术转移 |
| paper linked to trial | 基础研究到临床试验关联 |
| paper linked to project | 论文 funding / source |
| patent linked to project | 技术开发 funding / source |
| trial linked to project | 临床研究 funding / source |
| carrier mentions bioentity | carrier 到 Knowledge Unit 的映射基础 |

```text
9. sanity check 是否 PASS；
10. 输出结构是否能支撑后续 modeling dataset。
```

Stage 04 不是最终 temporal prediction benchmark。

## 4.2 Knowledge Unit 定义

当前工程版本采用：

```text
Knowledge Unit = typed BioEntity pair
```

即：

```text
z = (entity_i, entity_j, pair_type)
```

当前主版 translational / mechanistic pair types：

```text
chemical-disease
gene-disease
chemical-gene
```

当前不把 `disease-disease` 放入主版。原因是 disease-disease 共现混合了 comorbidity、complication、risk factor、subtype hierarchy、near-synonymy 和 background co-mention 等多种语义。

重要解释规则：

```text
carrier co-mention evidence does not imply an asserted biomedical relation.
chemical-disease pair != treatment claim
gene-disease pair != causal claim
chemical-gene pair != target claim
```

## 4.3 Canonicalization 策略

当前已修复 pair canonicalization：

```text
1. 不同类型 pair 按 pair_types 指定方向归一；
2. 同类型 pair 按稳定 entity key 排序；
3. reversed pair duplicate 被消除；
4. KU id 在 canonicalized pair 上生成。
```

sanity check 结果：

### 5.7.3 Forecasting protocol

正式第一版 benchmark 使用 expanding-window rolling-origin protocol：

```text
history_start_year = 2000
history_end_year = cutoff_year

future_start_year = cutoff_year + 1
future_end_year = cutoff_year + 3

horizon_years = 3
```

因为数据截止到：

```text
2024
```

所以最大 cutoff year 为：

```text
2021
```

对应：

```text
2021 -> future 2022-2024
```

2022-2024 不作为 cutoff history，而作为最新 test cutoffs 的 future supervision / target window 使用。

---

### 5.7.4 Train / validation / test split

正式第一版 split 固定为：

```text
train cutoffs:
  2005, 2006, 2007, 2008, 2009, 2010, 2011, 2012,
  2013, 2014, 2015, 2016

validation cutoffs:
  2017, 2018

test cutoffs:
  2019, 2020, 2021
```

其中：

```text
2000-2004 = warmup history
2005-2021 = prediction cutoff years
2022-2024 = latest future target years
```

对应 future windows：

```text
2005 -> 2006-2008
2006 -> 2007-2009
...
2016 -> 2017-2019

2017 -> 2018-2020
2018 -> 2019-2021

2019 -> 2020-2022
2020 -> 2021-2023
2021 -> 2022-2024
```

该 split 的原则：

```text
1. 每个样本都有完整 3 年 future window；
2. train / validation / test 按 cutoff year 分离；
3. test 使用最新年份，评估 temporal generalization；
4. 不使用随机 split，避免 temporal leakage；
5. 2000-2004 作为 warmup，避免过短历史导致特征不稳定。
```

### 5.7.5 三个主任务：Future heat forecasting

传统专利分析和技术预测通常关注：

```text
future activity
future growth
future intensity
future technology heat
future innovation potential
future ranking
```

因此，本研究的三个主任务不只定义为“是否出现 evidence”，而是定义为：

```text
Future heat / intensity forecasting
```

Binary emergence label 保留，但作为辅助标签和 classification evaluation view。

### 5.7.6 Task 1：Clinical Translation Heat Forecasting

任务目标：

```text
预测某个 KU 在未来窗口内的 clinical trial evidence intensity / heat。
```

未来计数目标：

```text
target_future_trial_count_3yr =
  sum_{τ = cutoff+1}^{cutoff+3} trial_count_year(z, τ)
```

未来权重目标：

```text
target_future_trial_weight_sum_3yr =
  sum_{τ = cutoff+1}^{cutoff+3} trial_pair_weight_sum_year(z, τ)
```

未来活跃年份：

```text
target_future_trial_active_years_3yr =
  count of years in future window where trial_count_year(z, τ) > 0
```

第一版 heat target：

```text
target_future_trial_heat_3yr =
  log1p(target_future_trial_count_3yr)
```

辅助 emergence label：

```text
label_future_trial_emergence_3yr =
  1[target_future_trial_count_3yr > 0]
```

Eligibility：

```text
eligible_trial_task =
  history_paper_count > 0
  AND history_trial_count == 0
```

解释：

```text
已有 scientific evidence，但尚未出现 clinical trial evidence；
预测未来 3 年是否以及多强地进入 clinical trial evidence。
```

## 8.2 Knowledge State 和 Knowledge Field

Knowledge State 不应被人工 rule-based proxy score 固定定义。

更合理的定义是：

```text
K_z(t) = Encoder_θ(X_z(≤t), S_z, G_t)
```

其中：

```text
X_z(≤t): KU 的历史 temporal evidence
S_z: KU static covariates
G_t: time-dependent graph context
K_z(t): learned latent Knowledge State
```

所有 knowledge units 的 states 构成 Knowledge Field：

```text
K(t) = {K_z(t)}_{z ∈ Z}
```

即：

```text
K(t) ∈ R^{|Z| × d}
```

## 8.3 Reaction-Diffusion-Source 动力学

核心模型可写为：

```text
dK(t)/dt = -D L_t K(t) + R_θ(K(t), X(t)) + S_θ(t)
```

其中：

| 项 | 含义 |
| --- | --- |
| K(t) | learned Knowledge Field |
| L_t | time-dependent KU graph Laplacian |
| D | diffusion coefficient |
| -D L_t K(t) | knowledge diffusion |
| R_θ | reaction term，知识增长、衰减、竞争、融合 |
| S_θ(t) | source term，funding / project / policy / external inputs |

异构边类型扩散可写为：

```text
dK/dt = Σ_{r ∈ R} D_r L_r K + R_θ(K, X) + S_θ
```

每种关系类型 `r` 有自己的 diffusion coefficient `D_r`。

## 8.4 模型模块

```text
Module 1: State Encoder
  K_t = Encoder_θ(X_t, S_t, G_t)

Module 2: Diffusion Layer
  Diff_t = Σ_r D_r L_r K_t

Module 3: Reaction Network
  React_t = MLP_θ([K_t, X_t, ΔX_t])

Module 4: Source Network
  Source_t = MLP_φ(Project / funding / source features)

Module 5: Prediction Heads
  ŷ_patent_heat
  ŷ_trial_heat
  ŷ_translation_heat
  p_patent_emergence
  p_trial_emergence
  p_translation_emergence
```

## 8.5 重要设计原则

```text
1. 不在 Stage 04F / Stage 05E 单独训练 encoder；
2. encoder 应作为 Stage 07 模型内部模块；
3. encoder 的作用通过主任务 ablation 评估；
4. 主任务应优先预测 future heat / ranking；
5. binary emergence classification 是辅助任务；
6. 解释性通过 attribution / ablation / counterfactual / path analysis 完成；
7. 不为了手工可解释性牺牲主任务预测性能；
8. 所有比较必须使用 Stage 05F frozen splits。
```

```text
  )
```

辅助二分类标签：

```text
y_z^translation_emergence(t, h) =
  1[
    patent_count_cum_z(t) = 0
    and trial_count_cum_z(t) = 0
    and sum_{τ=t+1}^{t+h}
      patent_count_z(τ) + trial_count_z(τ) > 0
  ]
```

这是当前推荐第一主任务。
